Gleaner Elasticsearch on port 9400

Analysis for adapting the ODIS search app (SEARCH_BACKEND=gleaner) · Cluster: http://odis.org:9400 · Generated 2026-07-27 (live probe)

The service on port 9400 is an Elasticsearch 8.15.3 cluster named mvp-gleaner, not a separate REST API. Your colleague’s update expands the corpus from four short-named gleaner-* indices to 45 per-source indices plus a unified odis index. Document shape is consistent, but source identifiers, index naming, and which index to query no longer match what odis-ui assumes today.

1. Executive summary

  • Unified search index: odis holds summoned records from many sources in one place. The source field uses ODISCat-style slugs (e.g. ocean-best-practices-system-obps), not the legacy short codes (obps, medin).
  • Per-source indices: New naming is gleaner-{slug} (e.g. gleaner-portal-marine-environmental-data-and-information-network). Legacy aliases gleaner-obps, gleaner-medin, gleaner-obis, gleaner-oe still exist and often contain more documents than the long-named twin or than odis for the same source.
  • Mapping fits the existing Gleaner query layer (name, description, type, source, jsonld, …) — but facet source IDs, display labels, index lists, and record routing in the API must be updated.
  • Graph noise in odis: Only ~12.6k of 30.5k documents match the app’s primary-type filter; the rest are structural JSON-LD nodes (schema:DataDownload, schema:Place, etc.), similar to the legacy odis_metadata problem.
  • IOOS-only in odis: ~13.3k documents have source = integrated-ocean-observing-system-ioos-data-catalog with no matching gleaner-{slug} index — federated search must use odis (or a new index) to surface them.

6. Recommended adaptations

P1 — Decide corpus strategy (with backend owner)

  1. Federated: Query single index odis for cross-source search (includes IOOS). Accept per-source caps until pipeline fills odis completely.
  2. Full per-source: Query gleaner-* with dynamic index list (exclude legacy shorts once long indices are authoritative).
  3. Hybrid: odis for global search + on-demand deep index for record detail when s3_key / slug routes to a per-source index.

P1 — Configuration

Add explicit mode instead of implicit four-index default, for example:

# Option A — federated
SEARCH_BACKEND=gleaner
GLEANER_ELASTICSEARCH_URL=http://odis.org:9400
GLEANER_INDICES=odis

# Option B — all summoned sources (exclude legacy duplicates carefully)
GLEANER_INDICES=gleaner-*

# Option C — transitional (current behavior, incomplete)
GLEANER_INDICES=gleaner-obps,gleaner-medin,gleaner-obis,gleaner-oe

Implement gleaner-* wildcard or startup discovery via _cat/indices/gleaner-* with a denylist for legacy short names when long indices are ready.

P2 — Source registry and record routing

  • Replace hardcoded GLEANER_SOURCES with labels from the catalogue index (main ES backend) keyed by slug, or a static JSON synced from ODISCat.
  • index_for_source(slug) → gleaner-{slug} (with legacy alias map: obps → ocean-best-practices-system-obps until data migration finishes).
  • get_record: try gleaner-{slug} first; fallback to odis with routing or ids query on id + source if per-source index missing (IOOS case).
  • Store _index in encoded record id or resolve via search-by-id if duplicates exist across indices.

P2 — Facets and filters

  • Source facet buckets will return slugs; UI already supports sourceLabel(id, name) when name is populated.
  • ?sources=obis will not match new documents; migrate API to accept slugs or map legacy query params.
  • Consider a terms aggregation size > 50 (currently 50) — cluster has ~39 sources in odis alone.

P3 — Health check

GleanerBackend.health() only checks indices.exists on the first configured index. For odis or wildcards, probe cluster health or HEAD /odis explicitly.

P3 — Type filter alignment

  • Extend _type_values_for_filter if harvest emits schema:Dataset on the same documents as primary hits (already partially handled via raw_types_for_filter).
  • Coordinate with pipeline to index searchable profiles only into odis (aligns with indexing-strategy.md).
